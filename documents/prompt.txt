## 역할

너는 Flutter 시니어 개발자다. 같은 Wi-Fi(LAN)에 접속한 사용자끼리 서버 없이 실시간 음성 대화를 할 수 있는
**워키토키(Push-to-Talk) 앱**을 Flutter로 만들어라.
진행하면서 의문사항은 꼭 물어볼것(grill-me)

## 개발 요구사항

1. **개발 언어/프레임워크**: Flutter (Dart 3+), 지원 플랫폼은 Android, iOS
2. **대상**: 같은 Wi-Fi(같은 서브넷)에 접속한 사용자. 인터넷 연결이나 별도 서버는 사용하지 않는다.
3. **기능**: 기본적인 워키토키 기능으로 대화한다.
4. **디자인**: 세련된 무전기 형태의 UI

## 기능 명세

### 1. 핵심 기능 (필수)
- **Push-to-Talk**: 화면의 큰 PTT 버튼을 누르고 있는 동안만 마이크 녹음 및 송신, 버튼을 떼면 송신 중단
- **반이중(Half-duplex) 방식**: 누군가 송신 중이면 다른 사용자는 수신만 가능. 수신 중에 PTT를 누르면
  송신이 거부되고 "채널 사용 중" 표시 및 햅틱 피드백
- **채널 선택**: 채널 1~16 중 선택. 같은 채널을 사용하는 기기끼리만 대화 가능
- **음량 조절**: 수신 볼륨 다이얼 (0~100%)
- **접속자 표시**: 같은 채널에 접속 중인 기기 수 및 닉네임 표시
- **닉네임 설정**: 최초 실행 시 입력, 설정 화면에서 변경 가능 (로컬 저장)
- **송/수신 상태 표시**: 대기(IDLE) / 송신(TX) / 수신(RX, 송신자 닉네임 표시)
- **효과음**: PTT 시작/종료 시 짧은 비프음(roger beep), 수신 시작 시 스퀠치 톤

### 2. 선택 기능 (여유 시 구현)
- 음성 활동 감지(VOX) 모드 토글
- 수신 오디오 노이즈 게이트
- 백그라운드 수신 (Android Foreground Service)
- 다크/라이트 테마 전환

## 네트워크 설계

서버 없이 동작하도록 **UDP 기반 P2P**로 구현한다.

- **전송 방식**: UDP 멀티캐스트를 기본으로 사용하고, 멀티캐스트가 제한되는 환경(특히 iOS)을 위해
  **서브넷 브로드캐스트를 폴백**으로 구현한다.
- **채널 매핑**: 채널 번호별로 멀티캐스트 그룹 주소 또는 포트를 분리한다.
  (예: 그룹 `239.255.42.X`, 포트 `45000 + 채널번호`)
- **패킷 구조** (직접 정의하되 아래 항목 포함):
  - 매직 넘버/버전, 패킷 타입(AUDIO / PRESENCE / TX_START / TX_END)
  - 송신자 ID(UUID), 닉네임, 채널, 시퀀스 번호, 타임스탬프, 페이로드
- **Presence**: 2~3초마다 PRESENCE 패킷을 송신하고, 일정 시간(예: 8초) 수신이 없으면 접속자 목록에서 제거
- **오디오 포맷**: 16kHz, 16bit, mono PCM을 20ms 프레임(640바이트) 단위로 전송.
  가능하면 Opus 코덱 적용(패키지 적합성 검토 후 결정, 어려우면 PCM 유지)
- **지터 버퍼**: 수신 측에 60~100ms 정도의 지터 버퍼를 두어 패킷 순서 뒤바뀜/손실에 대응.
  시퀀스 번호로 중복/역전 패킷 폐기
- **자기 자신의 패킷 무시**: 송신자 ID가 본인이면 재생하지 않는다.
- **보안**: 이번 범위에서는 암호화 없이 진행하되, 코드에 확장 포인트(주석)만 남긴다.

## 권장 패키지 (검토 후 더 적합한 것이 있으면 대체 가능, 이유를 설명할 것)

- 마이크 스트리밍: `record` (PCM16 스트림)
- PCM 스트림 재생: `flutter_soloud` 또는 `flutter_sound`
- 권한: `permission_handler`
- 네트워크 정보: `network_info_plus`, `connectivity_plus`
- 상태 관리: `flutter_riverpod`
- 로컬 저장: `shared_preferences`
- 햅틱/효과음: `HapticFeedback`(내장), 효과음 asset 재생
- 화면 꺼짐 방지: `wakelock_plus`

## 플랫폼별 필수 설정 (누락 없이 반영할 것)

### Android
- 권한: `INTERNET`, `RECORD_AUDIO`, `ACCESS_WIFI_STATE`, `CHANGE_WIFI_MULTICAST_STATE`, `ACCESS_NETWORK_STATE`
- 멀티캐스트 수신을 위한 `WifiManager.MulticastLock` 획득/해제 (MethodChannel로 네이티브 구현)
- (선택) 백그라운드 수신용 Foreground Service + 알림

### iOS
- `Info.plist`: `NSMicrophoneUsageDescription`, `NSLocalNetworkUsageDescription`, `NSBonjourServices`
- iOS의 멀티캐스트는 Apple의 `com.apple.developer.networking.multicast` entitlement 승인이 필요하므로,
  entitlement 없이도 동작하도록 **브로드캐스트 폴백 경로**를 반드시 구현하고 README에 이 제약을 명시
- 오디오 세션 설정(`playAndRecord`, 스피커 출력 기본)

## UI/UX 디자인 명세 (세련된 무전기 형태)

**컨셉**: 레트로-모던 하드웨어 무전기를 스마트폰 화면으로 옮긴 느낌. 스큐어모피즘과 플랫 디자인의 중간,
과하지 않고 고급스럽게.

- **전체 톤**: 다크 테마 기본. 무광 블랙/건메탈 그레이 바디 + 포인트 컬러 1개(앰버 오렌지 또는 네온 그린)
- **레이아웃 (위→아래)**:
  1. **안테나**: 화면 상단에 짧은 안테나 형태 디테일. 송신 중 은은한 글로우 애니메이션
  2. **상태 LED**: 대기(꺼짐/녹색 점멸), 송신(빨강), 수신(초록) 3색 LED
  3. **LCD 디스플레이 창**: 채널 번호(큰 7-세그먼트 스타일 폰트), 접속자 수, 닉네임/송신자 표시,
     신호(TX/RX) 레벨 미터. 액정 특유의 살짝 어두운 배경과 미세한 그리드/노이즈 텍스처
  4. **스피커 그릴**: 촘촘한 가로 슬릿 또는 원형 홀 패턴. 수신 중 음성 크기에 맞춰 미세하게 반응
  5. **채널 노브 / 볼륨 노브**: 회전형 다이얼 위젯 (드래그로 회전, 노치 단위 스냅, 회전 시 햅틱 틱)
  6. **PTT 버튼**: 하단 중앙의 크고 둥근 버튼(지름 화면 폭의 40% 이상). 눌리면 눌러 들어가는 애니메이션
     (그림자/하이라이트 변화), 송신 중 포인트 컬러 링이 펄스
- **모션**: 60fps 유지, 과하지 않은 마이크로 인터랙션 (노브 회전, 버튼 눌림, LED 전환, 레벨 미터)
- **폰트**: 채널 표시용 7-세그먼트/모노스페이스 폰트(Google Fonts 또는 asset), 그 외 보조 텍스트는
  깔끔한 산세리프
- **햅틱/사운드**: PTT 누름/뗌, 채널 변경, 채널 사용 중 거부 시 각각 다른 햅틱
- **반응형/접근성**: 세로 모드 고정, 작은 화면에서도 PTT 버튼이 엄지로 닿는 위치, 시맨틱 라벨 제공
- **CustomPainter/Canvas 활용**: 노브, 미터, 스피커 그릴 등은 이미지 asset 없이 코드로 그려서
  해상도에 상관없이 선명하게 구현 (가능한 범위에서)

## 화면 구성

1. **온보딩/권한 화면**: 마이크 및 로컬 네트워크 권한 요청, 거부 시 설정 이동 안내
2. **메인(무전기) 화면**: 위 UI 명세 전체
3. **설정 화면**: 닉네임, 기본 채널, 효과음 on/off, 햅틱 on/off, VOX(선택)
4. **Wi-Fi 미연결 상태 처리**: Wi-Fi에 연결되어 있지 않으면 메인 화면에 안내 배너 표시 및 송수신 비활성화

## 프로젝트 구조 (Feature-first)

```
lib/
  main.dart
  app/                    # 테마, 라우팅
  core/
    network/              # UDP 소켓, 패킷 인코딩/디코딩, 멀티캐스트/브로드캐스트 전송
    audio/                # 마이크 캡처, 재생, 지터 버퍼, 코덱
    utils/
  features/
    walkie/
      data/               # 트랜시버 서비스 구현, 패킷 모델
      domain/             # 엔티티(Peer, Channel, TxState 등)
      presentation/       # 화면, 위젯(노브, LCD, PTT 버튼, LED), Riverpod 컨트롤러
    settings/
    onboarding/
assets/
  sounds/                 # roger beep, squelch 등
  fonts/
test/
```

## 코딩 규칙

- `flutter analyze` 경고/에러 0개, `dart format` 적용
- 위젯은 작게 분리하고 `const` 적극 사용, 비즈니스 로직은 UI에서 분리(Riverpod Notifier/Service)
- 네트워크/오디오 리소스는 반드시 dispose 처리 (소켓 close, 스트림 cancel, 녹음 stop)
- 주요 로직(패킷 인코딩/디코딩, 지터 버퍼, 채널 상태 머신)은 단위 테스트 작성
- 매직 넘버는 상수로 분리 (포트, 프레임 크기, 타임아웃 등)

## 진행 방식

1. 먼저 **아키텍처와 패키지 선정 이유를 요약**하고, iOS 멀티캐스트 제약 대응 방안을 확인해서 알려줘.
2. 아래 순서로 단계별로 구현하고, 각 단계가 끝날 때마다 실행 방법과 검증 방법을 알려줘.
   - Step 1: 프로젝트 생성, 테마, 무전기 UI 뼈대 (기능 없이 화면만)
   - Step 2: 권한 처리 및 Wi-Fi 상태 감지
   - Step 3: UDP 송수신 및 Presence(접속자 목록)
   - Step 4: 마이크 캡처 → 패킷 전송 → 수신 → 재생 (PTT 동작)
   - Step 5: 지터 버퍼, 반이중 제어(채널 사용 중 처리), 효과음/햅틱
   - Step 6: 설정 화면, 예외 처리, 테스트, README
3. 실기기 2대 이상으로 테스트하는 방법(같은 Wi-Fi 연결, 확인 체크리스트)을 README에 정리해줘.

## 완료 기준 (Acceptance Criteria)

- [ ] 같은 Wi-Fi의 기기 2대에서 같은 채널로 PTT 송수신이 가능하다
- [ ] 다른 채널의 기기에는 음성이 들리지 않는다
- [ ] 송신 중에는 상대 기기에 송신자 닉네임과 RX 상태가 표시된다
- [ ] 수신 중 PTT를 누르면 송신이 막히고 안내가 표시된다
- [ ] 접속자 수가 실시간으로 갱신되고, 앱 종료/네트워크 이탈 시 자동으로 제거된다
- [ ] Wi-Fi 미연결 시 안내 배너가 뜨고 송수신이 비활성화된다
- [ ] 음성 지연이 체감상 300ms 이내이고, 끊김이 심하지 않다
- [ ] UI가 무전기 형태(안테나, LED, LCD, 스피커 그릴, 노브, PTT 버튼)로 구현되어 있다
- [ ] `flutter analyze` 통과, 핵심 로직 단위 테스트 통과

## 범위 제외 (이번에 하지 않는 것)

- 인터넷을 통한 원격 통화, 서버/계정 시스템
- 통화 녹음 저장, 텍스트 채팅, 파일 전송
- 종단간 암호화 (확장 포인트만 남김)
